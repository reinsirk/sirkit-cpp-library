# 暗黙Treap 414029の確認と追加比較（2026-10-30）

[414029](https://judge.yosupo.jp/submission/414029)は **AC・1157ms**。提出コードは現行本体65969ea6、main、共通入出力と一致した。414026の1476ms、414025の1283msより短い。混合の大規模3ケースは808/824/824ms、反転中心は1157ms、更新908ms、照会556msだった。[全オンライン結果](online-implicit-treap-414029-2026-10-30.json)へ保存した。

この差を最後の照会helperだけの効果とは扱わない。最遅の反転ケースはqueryを呼ばず、オンラインのseed・実行環境は制御できない。前回1476msの大幅退行の原因は依然として断定していない。

## 追加案

GCC15.2・C++23・O2・native、検査省略、同じmain/入出力、固定3seed各2回で比較した。初期比較は別のP-Core CPU4/8/12で実行したため、同じbaselineをcontrolとして使う対比較と、小さい差を区別した。E-Coreは使用していない。

| 案 | 重要な結果 | 判断 |
|---|---|---|
| 挿入のlengthを+1、集約だけ更新 | 挿入0.9954、混合0.9856 | 明確な利益に不足 |
| 挿入・削除のlengthを±1 | 削除1.1093、混合1.0344 | 不採用 |
| erase_prodでも増減を利用 | 削除1.1532、大規模erase_prod1.0756 | 不採用 |
| 集約をhelperではなく本文へ直接記述 | 削除1.1635 | 不採用 |
| split後のlengthを既知のkから算出 | 反転1.0659、control1.0189 | 不採用 |
| mergeの合計lengthを再帰前に保存 | 混合0.9823、control0.9810 | 明確な利益なし |
| splitとmergeの両方 | 削除1.1248、erase_prod1.083 | 不採用 |
| 存在が保証される子のnull判定を省く | helper版は削除1.1428、直接版は反転約2%短縮に対し挿入/混合は約1%増 | 追加の複雑さを採る根拠に不足 |

値は候補÷現行版の時間比中央値。lengthの読み直し自体は減るが、GCCの再帰展開が変わり、erase_nodeが0xc12から0x177バイトへ縮む例で削除が約16%遅くなった。生成コードが短いことを高速化の根拠にはしていない。

## 正しさと最終状態

候補の公式出力は全ハッシュ一致。挿入系とsplit系はそれぞれcompact可換/非可換・検査有効/無効の独立vector照合と境界試験に成功した。試作品の成功を現行の変更と混同しない。

追加案は採用せず、本体はオンラインACを照合したものからバイト単位で不変。公開API・main・共通入出力・使用例も変更していない。オンライン記録、最新URL、manifestと配布ZIPを同期した。**今回は再提出不要。** 同じ本体への重複した回帰試験の再実行も行っていない。
