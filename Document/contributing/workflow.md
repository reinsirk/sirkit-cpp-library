# 開発・CI・配布

## ファイルの配置

- ライブラリは用途別フォルダに置き、テンプレートはルートに残す。移動時は使用例・生成器・Verifyの参照を同期する。

## 開発とPR

- 開発はdevで進め、mainへの反映はGitHubのpull request経由とする。検証用のGitHub Actionsはmain向けPRの作成・更新時だけ起動し、devやmainへのpush単独では起動しない。PRでは生成物の同期・テスト・全件Verifyのローカル照合を行う。オンライン再提出は認証済み環境で別に行い、PRの実行だけでオンラインACと表示しない。READMEのVerify状況は現在のソースと判定記録からスクリプトで生成する。
- PRの配布版検査では、通常版・速度優先版と、共通・GCC専用・Clang専用・MSVC専用を組み合わせた全8版を対象にする。共通版は3処理系で、専用版は対応する処理系で構文検査と動作テストを行う。通常版は検査有効・省略の両方を検証し、無効な入力の失敗系は検査有効版で確認する。
- GitHub Pagesの公開はmainへマージしたPRを起点に行う。生成・公開手順は[ライブラリページ](../library_pages.md)を参照する。
- 既存の未コミット変更を保つ。

## 配布とローカルの検証資料

- 一時ログはGit管理外の`.sirkit-local/logs/`に保存する。公開しない実験資料は`.sirkit-local/experiments/`に置く。
- 配布はGitHub Releasesを使う。配布ZIPとそのmanifest・検査結果をリポジトリで維持せず、通常の改修時に再生成しない。添付用の個別ZIPが必要なときだけ既存の生成・検査ツールを使う。`Audit/data/`の検証ZIPもローカル保存とし、Gitの追跡対象や配布物に含めない。参照する履歴・SHAは維持し、ローカルで履歴を照合するときは必要なZIPを用意する。GitHub Actionsの検査をこれらのZIPへ依存させない。
