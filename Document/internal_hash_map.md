# 内部整数ハッシュ表

`reinsirk::detail::InternalHashMap<Key, Val, Packed, Denominator>`は動的BITと動的Union Findが共有する内部部品です。一般のキー、削除、反復子が必要なら[HashMap](hash_map.md)を使います。[使用例](../Examples/internal_hash_map_example.cpp)も参照してください。

キーはboolを除く64ビット以下の非修飾整数型です。値は既定構築・コピー代入可能である必要があり、表のコピーや`enumerate()`にはコピー構築も必要です。キー、値、占有情報を別々の配列に持ち、乗算ハッシュと線形探索を使います。ハッシュの係数はプロセス内で共有する時刻由来の奇数で、暗号学的な安全性はありません。

`Packed=true`は占有情報をビット単位で保持します。`Denominator`は2～8で、容量Cに対してC−floor(C/Denominator)件まで登録できます。既定値はfalseと5です。容量は8以上の2の冪で増やし、空の既定構築では配列を確保しません。容量上限の保護は`SKIP_RUNTIME_CHECKS`にかかわらず有効です。

`Packed=false`で旧容量が64以上の再確保では、占有情報をまとめて読み、登録済みスロットを元の順に移します。GCC/Clangのx86環境ではCPUのAVX2対応を確認して32件ずつ処理し、それ以外は標準C++23で8件ずつ処理します。`SIRKIT_DISABLE_SIMD`を定義するとAVX2実装とCPU判定を除外します。検索や再確保を伴わない追加は従来の線形探索です。

| 操作 | 動作・計算量 |
| --- | --- |
| `operator[](key)` | 未登録なら設定済み初期値を追加し、値の参照を返す。期待償却O(1)。 |
| `find_or_emplace(key, f)` | 未登録のときだけf()で値を作る。必要な再確保の後にfを呼ぶ。期待償却O(1)。 |
| `find(key)` | 値のポインタ、未登録ならnullptr。const版はconstポインタ。追加しない。期待O(1)。 |
| `find_nonempty(key)` | 容量が確保済みであることを前提とするconst検索。要素数0でも容量があれば使える。期待O(1)。 |
| `contains/contain/count` | 存在判定、または0/1を返す。期待O(1)。 |
| `reserve(n)` | n件まで再確保不要にする。縮小しない。再確保時は期待O(新容量)。 |
| `reallocate()` | 容量を2倍、未確保なら8にする。期待O(新容量)。 |
| `size/empty/capacity/load_factor` | 件数・空判定・スロット数・件数/容量。未確保の使用率は0。O(1)。 |
| `enumerate()` | キーと値をコピーしたvectorを順序不定で返す。非空はO(容量)、空はO(1)。 |
| `for_each(f)` | 各キーと値のconst参照でfを呼ぶ。非空はO(容量)、空はO(1)。 |
| `clear()` | 登録情報だけを消し、配列と各スロットの値の資源を保持する。非空はO(容量)、空はO(1)。 |
| `release()` | 配列とスロットの値を破棄し、未確保の空表に戻す。設定済み初期値は保持する。O(容量)。 |
| `set_default(value)` | 今後の`operator[]`追加に使う初期値をコピーする。既存値は変えない。 |
| `swap(other)` | 表・初期値・ハッシュ係数を交換する。値型のswap以外はO(1)。 |

上の計算量では値型のコピー・構築・破棄やコールバックの費用をO(1)としています。検索と再確保を伴わない追加の最悪計算量はO(容量)、再確保を伴う追加と再ハッシュはO(容量²)です。攻撃的なキー集合に対する計算量の保証はありません。空表を再確保する場合も新配列の初期化費用は残ります。

再確保・`release()`・表の代入で参照やポインタは無効になります。`reserve(n)`の後は登録数nまでの追加で再確保しません。`clear()`でスロットのオブジェクトは残りますが、その参照を登録値として使い続けないでください。`swap`やムーブでは参照先の所有者が移ります。

`find_or_emplace`のfactoryは表を変更せず、表内の要素への参照やポインタを使わないでください。呼び出し前に再確保する場合があります。`for_each`のコールバックも表を変更しないことが前提です。再確保時のコピーや値の代入が失敗しても登録件数は増えません。失敗した未登録スロットに値の資源が残る場合があります。値型自身の代入・swapが例外を投げる場合、初期値の変更を元に戻す保証はありません。

コピーは配列の深いコピーです。ムーブ後の元表は既定初期値を持つ未確保の空表となり、再利用できます。`clear()`でstringやshared_ptrなどの資源も解放したい用途では`release()`を使います。ただし初期値が所有する資源は保持されます。

提出先は[Library Checker Associative Array](https://judge.yosupo.jp/problem/associative_array)です。問題入力で使わないAPI・所有権・例外・型の組合せは独立したローカル照合で補います。測定結果と出典の調査根拠は[Audit](../Audit/)に置きます。
