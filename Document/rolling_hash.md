# バイト列のRolling Hash

文字列の各区間を多項式の剰余で表し、区間比較や共通接頭辞の照会に使います。[使用例](../Examples/rolling_hash_example.cpp)を参照してください。

底を`B`、法を`p=2^61-1`とし、各文字を`unsigned char`の値0〜255として扱います。接頭辞は`H[0]=0`、`H[i+1]=(H[i]*B+byte[i]) mod p`で構築し、区間`[l,r)`は`(H[r]-H[l]*B^(r-l)) mod p`で求めます。ハッシュ値は常に`[0,p)`です。文字コードの復号やUnicodeの正規化は行いません。埋め込みNULも、長さ付き`string_view`で渡せば値0のバイトとして扱えます。

## API

| API | 動作 |
| --- | --- |
| `RollingHash(s,base)` | バイト列から構築する。`base<2`は10、`base>p-2`は`p-10`へ補正する。 |
| `size()`、`empty()`、`base()` | 長さ、空か、補正後の底を返す。 |
| `get(l,r)` | 半開区間`[l,r)`のハッシュ。空区間は0。 |
| `whole()` | 全体のハッシュ。空なら0。 |
| `concat(left,right,right_length)` | 同じ底のハッシュを、右側の長さを指定して連結する。 |
| `equal(l,r,other,ol,orr)` | 2区間の長さとハッシュが等しいかを返す。底が同じこと。 |
| `lcp(l,other,ol,limit=SIZE_MAX)` | 2接尾辞の共通接頭辞長を、残長と`limit`以下で推定する。底が同じこと。 |
| `compare(l,r,other,ol,orr)` | 符号なしバイトの辞書順を推定し、-1/0/1を返す。底が同じこと。 |
| `assign(s)` | 現在の底を保って別の列へ置き換え、確保済み容量と利用可能な累乗表を再利用する。 |
| `clear()` | 空にし、底と確保済み容量を保持する。`noexcept`。 |
| `swap(other)`、`swap(left,right)` | 底と内容を交換する。`noexcept`。 |

`lcp`は同じ長さの区間ハッシュを比較して長さを二分探索します。両区間の開始接頭辞ハッシュの差が0なら、端点の接頭辞ハッシュを直接比較し、照会上限まで一致すれば直ちに返します。それ以外は先頭1文字の不一致と照会上限までの一致を先に調べ、残る場合だけ二分探索します。

区間は`0<=l<=r<=size()`です。`lcp`の開始位置は末尾も指定でき、上限は両方の残り長さと`limit`の最小値です。

`concat`には正規化済みのハッシュを渡し、`right_length<=size()`を満たしてください。このオブジェクトの累乗表を使うための長さ制約です。ハッシュと底・長さの対応は利用側で保ちます。

```cpp
constexpr std::uint64_t base = 911382323;
RollingHash text("abracadabra", base);
RollingHash word("abra", base);
assert(text.equal(0, 4, word, 0, 4));
assert(text.lcp(0, text, 7) == 4);
assert(text.concat(text.get(0, 4), text.get(4, 11), 7) == text.whole());
text.assign("banana");
assert(text.base() == base && text.size() == 6);
text.clear();
assert(text.empty() && text.whole() == 0 && text.base() == base);
```

## 衝突と比較の保証

異なる列が同じハッシュになる衝突があります。`equal`、`lcp`、`compare`は衝突により誤判定する可能性があり、厳密な文字列比較を保証しません。底は自動で乱数化しません。実行時に十分大きな底を選んで比較対象間で共有する方法は、固定した小さい底による衝突を避ける助けになりますが、衝突をなくす保証ではありません。

たとえば底2では`"adX"`と`"bbX"`の全体ハッシュが等しくなります。長さ1の接頭辞は異なり、長さ2と3の接頭辞は衝突するので、衝突時には「接頭辞のハッシュが一致する」という判定が長さに対して単調でなくなります。`lcp`の探索結果はハッシュに基づく推定値です。衝突した場合の探索結果は固定した仕様ではありません。

全体ハッシュだけでは列の長さを表しません。空列と値0のバイトだけの列はハッシュ0ですが、`equal`は長さも比較します。

## 演算と所有権

GCC/Clangで128ビット整数拡張が使える場合は乗算に使います。この拡張型は標準C++の型ではありません。対応しない環境、または`SIRKIT_FORCE_STANDARD_ARITHMETIC`を定義した場合は、32ビットに分けた4個の64ビット積を使う標準C++の経路を選びます。`2^61=1`、`2^64=8`を法`p`で利用して折り返します。

128ビット整数拡張を使う`concat`では、左ハッシュと累乗の積に右ハッシュを加えてから、折り返しと正規化をまとめます。正規化済みの`a,b,c<p`なら`a*b+c<p²`で、61ビットの折り返し後は`2p`未満なので、減算1回で正規化できます。右側の長さが0の場合は累乗表を参照しません。

`lcp`では開始接頭辞の差を`d=(H_A[l]-H_B[ol]) mod p`として先に求めます。長さ`t`の区間ハッシュの一致は`H_A[l+t]-H_B[ol+t]-d*B^t≡0 (mod p)`と同値なので、各探索で必要な乗算は1回です。`d=0`なら乗算も省けます。

128ビット経路の一致判定は`X=d*B^t+(H_B[ol+t]+p-H_A[l+t])`をまとめて計算します。累乗は正規化済みで、`0<X<=p²`です。61ビットで折り返した値は`0<fold(X)<2p`なので、`p`との一致だけで剰余0を判定できます。標準C++経路では4個の64ビット積による値を使い、正の差を`6p`未満に保って同じ判定を行います。`get`や`concat`の戻り値は引き続き`[0,p)`です。

GCCのx86_64向け標準算術経路では、構築と`assign`のループを4文字ずつ展開します。各文字の演算順を保ち、残り1〜3文字は通常のループで処理します。小さい列では展開と端数処理の費用が増える場合があります。

128ビット整数拡張を使うGCC/Clangのx86_64では、4,096文字以上の構築でCPUのAVX2対応を確認します。対応時は4文字分の接頭辞と累乗を、それぞれ4本並列に計算します。`c*B`、`c*B²`、`c*B³`の剰余を256要素ずつの作業表に置き、ブロック開始時の`H`に`B`〜`B⁴`を掛けて各接頭辞を求めます。累乗も同じ4個の因子で進めます。残り1〜3文字は通常の演算で処理します。

SIMDの各乗算は32ビットの4部分積で計算します。文字項を含む和は`7p`未満で64ビットに収まります。次の計算へは`[0,p+6]`の同じ剰余を渡し、保存するハッシュだけを`[0,p)`へ正規化することで、正規化の待ち時間を減らします。作業表はスタック上の約6 KiBで、オブジェクトの保持領域やヒープ確保は増えません。

累乗表を再利用できる`assign`では、接頭辞だけを4本並列に計算し、累乗の計算と出力を省きます。非対応CPU、小さい列、標準算術を強制した場合は通常の処理です。貼り付け前に`SIRKIT_DISABLE_SIMD`を定義すると、AVX2専用処理と追加のCPU判定を除外できます。AVX2の対象指定は内部関数だけに付けるため、プログラム全体への`-march=native`指定は不要です。

`equal`も開始接頭辞の差と端点から区間ハッシュの差を計算し、乗算1回で比較します。開始接頭辞が同じなら端点を比較するだけです。`compare`ではLCP長を`k`とすると、長さ`k+1`の区間ハッシュ差は次の1バイトの差になります。上記の積和`X`を`t=k+1`で求め、その折り返し値が`p`なら差0、それ以外はbit60が1なら左区間が大きく、0なら右区間が大きいと判定します。符号なしバイト同士の差が`[-255,255]`に限られることを利用しています。標準算術経路では差を逆向きに取るため、返す符号も逆にします。LCP長は前述の探索で求めます。

接頭辞と底の累乗をそれぞれ`vector`で所有します。元の文字列は保存せず、構築・`assign`完了後は入力の`string_view`や参照元文字列を保持する必要がありません。累乗領域への内部ポインタは非所有で、コピー・ムーブ・交換時に対応する配列と整合を保ちます。

コピーは独立します。コピー代入と`assign`は両配列の必要な容量を先に確保し、その後に非送出の書込みを行います。確保に失敗しても内容・底・内部参照を保ちますが、内部の確保済み容量は増えている場合があります。容量内の置換では新たな確保を行いません。`assign`時に必要な長さの累乗表が残っていれば、底が変わらないためその表も再利用します。`clear`後と列を長くする場合は接頭辞と累乗を同じループで作ります。ムーブ後の移動元は空になり、底は保持します。自己代入・自己ムーブでは内容を保ちます。

## 計算量と入力検査

列の長さを`n`とすると構築はO(n+1)時間・領域です。`get`、`whole`、`concat`、`equal`、`size`、`empty`、`base`、`swap`はO(1)です。`lcp`は両方の残長と`limit`の最小値を`m`としてO(1+log(m+1))、`compare`は短い方の長さを`m`としてO(1+log(m+1))です。

コピー構築はO(n+1)、コピー代入と`assign`は旧長`n`・新長`m`に対してO(n+m+1)の上界で、容量を増やす場合は、確保中に配列の新旧領域を使います。ムーブ構築はO(1)、ムーブ代入は旧状態の破棄を含めO(n+1)の上界です。`clear`は標準コンテナの保証に基づきO(n+1)の上界です。保持領域は両配列の確保済み容量の合計を`C`としてO(C+1)で、`clear`は容量を保持します。

既定では不正な区間・連結長を`out_of_range`、底の不一致・正規化されていないハッシュを`invalid_argument`で拒否します。`SKIP_RUNTIME_CHECKS`で入力検査と検査専用の関数を除外します。容量の内部上限は検査省略時も維持します。検査のためだけに列を走査せず、渡されたハッシュと元の列の対応を検証する機能はありません。
