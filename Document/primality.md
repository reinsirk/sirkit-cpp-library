# 素数判定と隣接素数

符号付き・符号なしの64ビット以下の整数を判定します。`is_prime`は`uint64_t`全域で確定的に判定し、`MillerRabin`は利用側が指定した底の強擬素数検査を行います。[使用例](../Examples/primality_example.cpp)を参照してください。

## API

| API | 動作 |
| --- | --- |
| `is_prime(n)` | 素数なら`true`。負数、0、1は`false`。 |
| `MillerRabin(n,bases)` | 指定した各底の強擬素数検査をすべて通れば`true`。底の選び方によって合成数も通る。 |
| `MillerRabin(n,{2,7,61})` | `initializer_list<uint64_t>`で底を直接指定する。 |
| `next_prime(n)` | `n`以上で最小の素数を`optional<uint64_t>`で返す。表現範囲内にない場合は`nullopt`。負数なら2。 |
| `prev_prime(n)` | `n`以下で最大の素数を同じ型で返す。`n<2`なら`nullopt`。 |

引数`n`は64ビット以下の整数型です。隣接素数の戻り値は、引数の型にかかわらず`uint64_t`です。`next_prime`と`prev_prime`は、入力が素数ならその値自身を返します。

```cpp
assert(is_prime(998244353));
assert(!is_prime(-7));
assert(*next_prime(24) == 29);
assert(*prev_prime(24) == 23);
assert(*next_prime(29) == 29);
assert(!prev_prime(1));
```

## 固定底と指定底

`is_prime`は小さな素数による除算を先に行い、残りをMiller–Rabin法で判定します。32ビットを超える値では、3・5・7との共通因子を105通りの剰余と16バイトの静的なbit表でまとめて調べ、11・13・17の倍数も除外します。32ビット以下は共通の専用判定を使います。32ビット以下と4,759,123,141未満では底2、7、61を使い、それ以上では底2、325、9375、28178、450775、9780504、1795265022を使います。7底の判定では最初に底2を調べ、通過後に残りを3底ずつ同時に進めます。各3底の累乗には2ビット窓を使い、0〜3乗の小さな表を作って、指数の上位から平方と必要な積を進めます。底2と指定底の判定には二進累乗を使います。

底2、7、61の最小の同時強擬素数は4,759,123,141なので、この保証は境界値を含みません。[Jaeschke論文](https://doi.org/10.1090/S0025-5718-1993-1192971-8)のp.926で確認できます。7底の`uint64_t`全域の記録は、[Izykowskiが管理するSPRP記録表](https://miller-rabin.appspot.com/)でJim Sinclairに帰属されています。

`MillerRabin`は、符号付きの負の底を含め、各底を`n`で割った剰余として扱います。剰余0の底は省きます。`n<2`なら`false`、偶数なら`n==2`です。奇数`n>=3`で底が空、またはすべて省かれる場合は`true`になります。

```cpp
assert(MillerRabin(2047, {2})); // 2047は合成数でも底2を通る。
const std::array<std::int64_t, 2> bases{-2, 3};
auto probable = MillerRabin(97, bases);
```

底は64ビット以下の整数型の値を返す範囲を渡します。負の底は符号付き配列などで指定します。整数リスト版の要素型は`uint64_t`です。

## 整数演算と計算量

Montgomery乗算で累乗中の剰余を求めます。GCC／Clangで128ビット整数拡張を使える場合は利用します。これは標準C++の型ではありません。`SIRKIT_FORCE_STANDARD_ARITHMETIC`を定義すると標準C++の代替経路を選びます。代替経路では64ビット積を32ビットずつに分割し、上位への桁上がりも扱います。

GCCのx86環境では、glibc 2.23以降のELF形式で128ビット整数拡張が使える場合に、3底を同時に調べる内部関数へBMI2版と通常版を生成します。CPUに応じて選び、非対応CPUでは通常版を使います。BMI2はスカラー整数命令で、SIMDではありません。`SIRKIT_DISABLE_SIMD`を定義すると、この専用版とCPUによる選択も除外します。Clang、標準演算への強制切替、BMI2をコンパイル時に有効にしている場合は、この追加の切替を使いません。

64ビット用の乗算では、`R=2^64`として法`n`の逆元を`R`上で求めます。積`a*b`と、同じ下位64ビットを持つ`m*n`の上位64ビットを引けば、下位の桁上がりを計算せずにMontgomery還元できます。

`n<2^62`では入力を`2*n`未満に保ち、上位の差に常に`n`を足します。結果は`2*n`未満で、必要な箇所だけ正規化します。これ以上の法では、差が負の場合だけ`n`を加え、常に`n`未満を返します。減算と補正は符号なし整数で行い、`uint64_t`上端でも符号付きオーバーフローを起こしません。

64ビット整数演算をO(1)とすると、`n>=2`で底`k`個の判定はO(k log(n+1))時間、O(1)追加領域です。小さい入力はO(1)で返します。`is_prime`の底の個数は定数です。隣接素数の探索は候補を順に判定し、調べた候補数を`c`、判定対象の最大値を`N`としてO(1+c log(N+1))時間、O(1)追加領域です。範囲端では加減算前に境界を確認し、ラップアラウンドさせません。

## 状態と例外

判定用の法や累乗定数は各呼出し内に持ちます。ライブラリ自身は動的確保を行いません。底列は参照して走査し、保持しません。

`is_prime`、隣接素数、整数リスト版は`noexcept`です。汎用の底列版は、iteratorとsentinelの構築・比較・読取・増分・破棄を含めて条件付き`noexcept`を判定します。ADLだけで走査できる列では保守的に`noexcept(false)`とし、走査中の例外を呼出し元へ伝えます。`SKIP_RUNTIME_CHECKS`で負数・0・1の扱いや桁上がり対策は省略しません。
