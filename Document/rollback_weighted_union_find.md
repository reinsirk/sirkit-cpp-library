# 巻き戻せる重み付きUnion Find

頂点間の差を持つ連結成分を管理し、追加した制約を逆順に取り消します。探索中に条件を追加して戻す処理や、オフライン動的連結性に使えます。[使用例](../Examples/rollback_weighted_union_find_example.cpp)を参照してください。

`unite(x,y,w)`の向きは`potential(y)-potential(x)=w`です。小さい成分を大きい成分へ接続し、各子には親からの差を保存します。子となるたびに成分サイズが少なくとも2倍になるので、木の深さはO(log(n+1))です。経路圧縮は行いません。根のポテンシャルを0とした各頂点への差は、経路上の重みの和で求めます。

同じ親を持つ子どうしの`try_diff`では、親から上の共通経路を打ち消して保存差から答えます。GCCの`consistent`にもこの省略を使います。符号付き整数を標準C++の2語で累積する場合は、両APIとも根までの重みを求める経路を使います。

## API

| API | 動作 |
| --- | --- |
| `RollbackWeightedUnionFind<T>()` | 空で構築する。 |
| `RollbackWeightedUnionFind<T>(n)` | `n>=0`頂点を別々の成分として構築する。 |
| `find(v)` | 代表頂点を返す。 |
| `same(x,y)` | 同じ成分かを返す。 |
| `size(v)` | 指定頂点の成分サイズ。 |
| `root_with_weight(v)` | `{代表, 代表からvへの差}`を返す。 |
| `get_weight(v)` | 代表から`v`への差を返す。 |
| `diff(x,y)` | `potential(y)-potential(x)`を返す。同じ成分であること。 |
| `try_diff(x,y)` | 同じ差を`optional<T>`で返し、別成分なら`nullopt`。 |
| `consistent(x,y,w)` | 別成分なら`true`、同じ成分なら現在の差が`w`と等しいかを返す。 |
| `unite(x,y,w)` | 成分を結合し、新しく結合した場合だけ`true`。既結合時は差を検査しない。 |
| `unite_checked(x,y,w)` | 新規結合・既に整合・矛盾を`MergeResult`で返す。 |
| `get_state()` | 現在残っている追加呼出し数を返す。 |
| `snapshot()` | 現在の履歴位置を1個だけ保存する。 |
| `undo()` | 直前の追加呼出しを1回戻す。履歴が空でないこと。 |
| `rollback(state=-1)` | 指定位置まで戻す。`-1`なら保存した位置まで戻す。 |
| `clear_history()` | 連結状態と差を保って履歴・保存位置を0にし、履歴容量を保持する。 |
| `reserve_history(k)` | `k`回分の履歴容量を確保する。 |
| `size()`、`empty()`、`component_count()` | 全頂点数、空か、成分数。 |
| `groups()` | 成分ごとの頂点一覧。各一覧の頂点は昇順。 |
| `reset(n)`、`reset()` | 指定した頂点数、または現在の頂点数で全成分を独立にし、差・履歴・保存位置を初期化する。 |
| `clear()` | 空へ戻し、各配列の確保済み容量を保持する。 |
| `swap(other)`、`swap(a,b)` | 重み・履歴・保存位置も含めて内容を交換する。 |

`MergeResult`は`Merged`、`AlreadyConsistent`、`Contradiction`です。冗長な制約と矛盾した制約も、例外が起きなければ履歴を1回進めます。矛盾した追加は成分や差を変更しません。成分全体に矛盾フラグを残すAPIではありません。

```cpp
using UF = RollbackWeightedUnionFind<std::int64_t>;
UF uf(3);
assert(uf.unite(0, 1, 4));
uf.snapshot();
assert(uf.unite(1, 2, -7));
assert(uf.diff(0, 2) == -3);
assert(uf.unite_checked(0, 2, 9) == UF::MergeResult::Contradiction);
uf.undo(); // 矛盾した追加だけを戻す。
uf.rollback();
assert(uf.same(0, 1) && !uf.same(0, 2));
```

## 重みの型と整数範囲

`T`には0の構築、コピー・ムーブ・代入、`+`と`-`を備える可換加法群を指定します。`consistent`と`unite_checked`には`==`も必要です。利用側で用意したmodintも使えます。 算術の内部引数は、自明なコピー型または非const左辺を必要とする型では値で渡し、それ以外ではconst参照で渡してコピーを抑えます。符号なし整数は型の幅の剰余として扱います。浮動小数点の丸め誤差を吸収する許容誤差判定はありません。

標準の符号付き整数では、経路の途中和が型の範囲を超えても、広い累積値で相殺を保ちます。`get_weight`と`root_with_weight`の返す根からの差、`diff`と`try_diff`の返す頂点間の差は、最終値が`T`の範囲外なら`overflow_error`です。両頂点の根からの差が個別には`T`の範囲外でも、差の最終値が収まれば返せます。

新規結合では、サイズによって選んだ根同士を結ぶ差を`T`に保存できることが必要です。この差が範囲外なら、入力の`w`が範囲内でも`overflow_error`になります。`consistent`が返すのは制約の論理的な整合性であり、この保存時の表現可能性ではありません。

GCC/Clangで128ビット整数拡張が利用可能なら累積値に使います。これは標準C++の型ではありません。利用できない場合、または`SIRKIT_FORCE_STANDARD_ARITHMETIC`を定義した場合は、符号と2桁の符号なし整数で累積する標準C++の代替実装を使います。通常幅で安全な経路は広い演算を避け、必要な場合だけ再走査します。保存した辺の絶対値による安全判定は、巻き戻した後も保守的に保持します。

## 履歴と保存位置

頂点は`0<=v<size()`、履歴位置は`0<=state<=get_state()`です。履歴数は`INT_MAX`以下です。`get_state()`の整数は、現在残っている枝の位置です。捨てた枝や別インスタンスの状態を再び選べる永続的な版ハンドルではありません。

`snapshot`の保存枠は1個です。保存位置より手前へ`undo`や`rollback`した場合、保存位置も到達位置へ切り詰めます。`reset`と`clear`は履歴と保存位置を消し、整数経路の安全判定も初期状態に戻します。引数なし`reset()`は頂点数を保ちます。巻き戻しでは履歴の確保済み容量を保持します。

`clear_history()`は、現在の成分と差を新しい履歴の開始点にします。例外を送出せず、`get_state()`と保存位置は0になります。確保済み履歴容量と整数経路の保守的な安全判定は保持します。消去前の状態位置は無効です。

```cpp
uf.clear_history();
assert(uf.get_state() == 0 && uf.diff(0, 1) == 4);
uf.unite(1, 2, 6);
uf.rollback(0);
assert(uf.diff(0, 1) == 4 && !uf.same(0, 2));
```

## 計算量と所有権

以下は`T`の演算・コピー・破棄をO(1)として数えます。頂点数を`n`、現在の履歴長を`h`、確保済み履歴容量を`H`とすると、保持領域はO(n+H+1)です。構築はO(n+1)、コピーは履歴も含めてO(n+h+1)時間・領域で独立です。

代表・重み・差・整合性の照会はO(log(n+1))、各追加は履歴の再確保を含めて償却O(log(n+1))時間です。`undo`はO(1)、`rollback`は戻す追加数を`k`としてO(1+k)です。`clear_history`は標準コンテナの保証に基づくO(h+1)の上界です。`groups`はO(1+n log(n+1))時間、O(n+1)追加領域です。全頂点が別成分または全頂点が1成分なら、代表探索を省いてO(n+1)時間で一覧を作ります。Clang以外では根の負サイズから出力容量を確保し、代表から出力位置への作業配列1本で頂点を並べます。Clangの標準経路は代表・件数の2配列を使います。`reserve_history`は再確保する場合O(h+1)、しない場合O(1)です。

Clangのx86で、コンパイル時にAVX2が有効になっておらず、実行CPUがAVX2に対応している場合、256頂点以上の`groups`は代表探索を8頂点ずつ処理します。未解決の親だけをmasked gatherで追い、代表を求めてから出力領域を確保します。根の負サイズも使い、作業配列は代表・成分位置の2本です。既にAVX2が有効なコンパイル設定では、自動ベクトル化を使う従来の標準処理を選びます。`SIRKIT_DISABLE_SIMD`を定義すると追加のAVX2実装・対応ヘッダー・CPU判定を除外します。公開APIと親配列・履歴はどの経路でも同じです。

`size()`、`empty`、`component_count`、`snapshot`、`get_state`、`swap`とムーブ構築はO(1)です。`clear`はO(n+h+1)の上界です。`reset(m)`は旧状態の破棄も含めてO(n+h+m+1)時間です。`T`のコピー構築と破棄が例外を送出せず、頂点と重みの容量が足りる場合は、0を表す`T(0)`を先に構築して領域を再利用します。履歴を含めた予約を全て済ませ、親配列の要素数を合わせて全頂点を独立へ戻します。親と、コピー代入も例外を送出しない重みは、増加分を`resize`で初期化し、保持していた先頭の`min(旧要素数,m)`個だけを再代入します。代入が例外を送出し得る型では既存要素を破棄してからコピー構築し直します。十分な容量があれば内部配列の再確保を省きます。`T`自身の動的確保は型の実装に依存します。容量が足りない場合と、それ以外の型では従来どおり新しい状態を一時構築してから交換するため、一時的に新旧両方の領域を使います。再利用する場合は容量を減らしませんが、一時構築する場合は新しい状態の容量になります。ムーブ代入では、代入先の旧状態を破棄する費用もかかります。ムーブ後の移動元は空です。

所有には標準コンテナを使います。コピー代入は従来どおり引数を値で受け取り、構築後に交換します。`reset`は上記の型条件に応じて領域の再利用か一時構築を選びます。`T(0)`の構築や容量確保が失敗しても、連結状態・差・履歴・保存位置は保ちます。先行した予約によって容量は増える場合があります。標準整数や通常のmodintのように値の代入が例外を送出しない型では、結合時の履歴確保失敗でも既存の連結状態と履歴を保ちます。任意の独自型の演算や、値を変更してから例外を送出する代入に対して、全操作で状態維持を保証するものではありません。

有効な履歴への`undo`と`rollback`では、独自`T`の構築・代入・算術を行いません。根になった頂点の保存重みは参照せず、各照会で根からの差を0として扱います。標準整数では、照会の高速経路に合わせて保存重みも0へ戻します。

[成分列挙と再初期化の独立モデル](../Verify/current/tests/rwuf_groups_reset_reference_test.cpp)では、任意の頂点順、非零の重みの巻き戻し、縮小・再拡大、明示した0と既定値が異なる型も確認します。

非零の重みを戻す処理は、辺集合を保存してBFSで差を求める独立参照と比較します。ローカル検査ではundo・snapshot・多件のrollback・矛盾履歴・整数の範囲端も扱います。オンライン2問題だけで全APIを検証したとはしません。

## 入力検査

既定では頂点、空履歴への`undo`、不正な巻き戻し位置、未連結の`diff`を拒否します。検査のためだけの全頂点・全履歴走査は行いません。`SKIP_RUNTIME_CHECKS`を定義した場合は利用側でこれらの前提を満たしてください。容量と符号付き整数の演算保護は、検査省略時も維持します。

現行実装のCC0宣言と、由来を確認できない旧版との区別は[来歴とライセンスの監査](../Audit/provenance-rollback-weighted-union-find-second-pass-2026-10-22.json)を参照してください。
