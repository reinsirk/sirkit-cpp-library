# 最長増加部分列

数列の順序を保って要素を選び、狭義または広義の増加列を求めます。`Strict=true`は狭義、`false`は広義です。比較には`operator<`を使います。[使用例](../Examples/lis_example.cpp)を参照してください。

長さごとに末尾の最小値を保持し、次の要素を置く位置を二分探索します。狭義は同値の手前、広義は同値の後ろへ置きます。末尾より大きい要素は探索せず延長できます。復元では各長さの末尾の添字と前駆添字を記録し、最後からたどります。

## API

| API | 戻り値 |
| --- | --- |
| `LIS<Strict>(v)` | 各接頭辞の最長部分列の長さを`vector<size_t>`で返す。Strictを指定する。 |
| `LISLength<Strict=true>(v)` | 全体の最長部分列の長さを`size_t`で返す。 |
| `LISEndingLengths<Strict=true>(v)` | 各位置を末尾とする最長部分列の長さを`vector<size_t>`で返す。 |
| `LISIndices<Strict=true>(v)` | 最長部分列を1つ復元し、元の配列の添字を昇順で返す。 |
| `LISSequence<Strict=true>(v)` | 最長部分列を1つ値の列としてコピーして返す。 |

空入力では長さ0、各vectorは空です。同じ長さの解は複数あり、選択される列は規定しません。元の配列は変更しません。

```cpp
const std::vector<int> a{3, 1, 2, 0};
auto prefix = LIS<true>(a);        // {1, 1, 2, 2}
auto ending = LISEndingLengths(a); // {1, 1, 2, 1}
```

接頭辞長はその位置までの最大長、末尾長はその要素を必ず使う列の長さです。末尾長の最大値が全体長になります。

## 計算量と型

Nを入力長、Lを最長部分列長とします。全APIはO(N log(L+1))時間です。順に延長できる入力はO(N)時間で処理します。追加領域は長さだけの`LISLength`がO(L)、接頭辞長と末尾長がO(N+L)、復元がO(N)です。値列では選択したL個の値もコピーします。Tの比較・コピーを定数時間とした評価です。

`operator<`は一貫した狭義弱順序を定める必要があります。同値は`!(a<b) && !(b<a)`です。`operator==`や`operator<=`は不要です。標準浮動小数点型のNaNはこの前提を満たさないため、既定では通常の処理ループで検出して`invalid_argument`を投げます。追加の全配列走査は行いません。`SKIP_RUNTIME_CHECKS`を定義するとこの検査を除外するため、NaNを含めないことが利用側の前提です。正負の無限大は順序が成立する値として扱えます。汎用型の比較の一貫性まで検証するものではありません。

長さ系APIはTを作業領域へコピー・代入するため、コピー構築とコピー代入が必要です。`LISIndices`は汎用型のコピー・代入やdefault構築を必要とせず、比較だけで処理します。8バイト以下の組込み数値型では、末尾値を内部へ複製する場合があります。`LISSequence`には選択値のコピー構築が必要です。

作業領域は`std::vector`と`std::unique_ptr`、戻り値は`std::vector`が所有し、入力への参照を戻り値に保持しません。確保・比較・コピーで例外が起きた場合は局所領域を破棄して例外を伝え、入力を保持します。必要な領域を確保できない場合は標準の容量・確保例外が伝わります。

提出先は[Library Checker Longest Increasing Subsequence](https://judge.yosupo.jp/problem/longest_increasing_subsequence)です。狭義の添字復元を問題で確認し、広義・各長さ・値列・汎用型は独立ローカル検査で補います。出典とライセンスの根拠は[監査記録](../Audit/provenance-lis-2026-10-22.json)に置きます。

復元では末尾へ延長できるかと先頭へ置換できるかを先に調べます。どちらでもなければLIS長は2以上で、置換位置は2番目から末尾までです。末尾の比較結果を再利用し、その手前だけを二分探索します。

復元の内部添字は、入力長が`UINT32_MAX`以下なら32ビット、それを超えれば`size_t`を使います。公開する添字型は常に`size_t`です。大規模な組込み数値列では先頭256要素の比較状況から、末尾値を連続領域へ保持する方法を選ぶ場合があります。部分列が長く伸び続ける場合は添字だけの処理へ移り、値の作業領域は復元前に解放します。いずれも通常の狭義・広義の順序比較を使い、入力値や解の性質を前提として省略しません。

GCC 15.2のx86-64では、狭義・`std::int64_t`の復元を専用処理で高速化する。値を保持する経路では、候補範囲が32〜4096要素なら3点を独立に比較して4分割し、比較結果の符号なしマスクから次の区間を求める。最初の1段はループ外で処理する。

AVX2対応CPUでは、最後の候補が8〜15件なら先頭8件と末尾8件を重ねて読み、独立に比較して位置を確定する。4〜7件なら先頭4件を比較し、残りは二分探索する。残件数を確認してから読むため、配列のサイズ外を読み込まない。CPUの対応確認は経路を選ぶときに行い、探索ごとには行わない。非対応CPUでは標準の処理を使う。

先頭256要素で部分列の長さが64を超える大規模入力では、添字だけの経路を使い、部分列の長さが34未満、34〜4098、4099以上の3段階に分ける。中間の段階だけ最初の1段を4分割し、残りは二分探索する。段階の切替は延長時に判定し、短い部分列の探索へ毎回の範囲判定を加えない。

`SIRKIT_DISABLE_SIMD`を定義すると専用処理とCPU判定を除外する。広義・他の型・他のコンパイラも従来の標準処理を使う。公開API、計算量、使用メモリは同じで、復元される同長解の選択は規定しない。

大規模な数値型、探索区間・値保持の切替境界、NaNの位置、確保失敗は[独立したFenwick最大DPとの照合](../Verify/current/tests/lis_cache_reference_test.cpp)で検証する。

SIMDの読込み境界と3段階の遷移は、[専用の独立参照試験](../Verify/current/tests/lis_simd_phase_reference_test.cpp)で、公開APIと内部の32/64ビット添字経路を照合する。
